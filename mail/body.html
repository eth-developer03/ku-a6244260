#1 Tests-as-data replay harness for AI-edited Spring Boot services4.8
↻ repeat signal · 8 days
A tool that stores API behaviour as versioned YAML or JSON test cases exported from production traffic and replays them against any branch an AI agent has edited. It reports behaviour diffs, not just pass or fail, so reviewers can see what the agent changed. Sell it as a CI plugin to backend teams that let coding agents open pull requests.
Effort 2/5 · Cost 1/5 · Fit 5/5 (lower effort and cost are better)
Why now: Matteo Vaccari's Martin Fowler piece argues that customer-level tests stored as data should be the contract an AI agent cannot edit, and GitHub's agent-scale work shows agent-written changes are becoming routine.
First step: Export thirty real request and response pairs from one internal Spring Boot service into a YAML file, then replay them against a branch an agent has edited.

#3 Tool-identity guard for MCP servers in agent backends4.0
↻ repeat signal · 8 days
A Java or Python library and sidecar that pins each MCP tool to a verified provider and rejects calls that resolve to an unexpected server. It also enforces per-tool permissions and writes an audit trail of every tool resolution. Sell it to teams that run several MCP servers inside internal agent platforms.
Effort 3/5 · Cost 1/5 · Fit 4/5 (lower effort and cost are better)
Why now: A new arXiv paper shows an attacker-controlled MCP server can capture tool calls by advertising matching names and metadata, with no host or model compromise needed.
