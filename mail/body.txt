BUSINESS IDEAS
1. Tests-as-data replay harness for AI-edited Spring Boot services (score 4.8; effort 2, cost 1, fit 5)
   A tool that stores API behaviour as versioned YAML or JSON test cases exported from production traffic and replays them against any branch an AI agent has edited. It reports behaviour diffs, not just pass or fail, so reviewers can see what the agent changed. Sell it as a CI plugin to backend teams that let coding agents open pull requests.
   Why now: Matteo Vaccari's Martin Fowler piece argues that customer-level tests stored as data should be the contract an AI agent cannot edit, and GitHub's agent-scale work shows agent-written changes are becoming routine.
   First step: Export thirty real request and response pairs from one internal Spring Boot service into a YAML file, then replay them against a branch an agent has edited.

2. Reimbursement and benefits payout API for Indian SMB employers (score 4.2; effort 3, cost 2, fit 5)
   A payout API for mid-size Indian employers to pay medical, travel and fuel reimbursements to employees' bank accounts with bank-account validation, retries and an audit log. Build it on top of a licensed payout partner instead of holding funds yourself, so compliance cost stays low. Target HR and finance teams at startups that still pay claims through monthly spreadsheets.
   Why now: Y Combinator's profile of Varsha Parthasarathy at Flex describes building to fix HSA and FSA payment failures she personally hit, which shows benefits payouts are still broken in practice.
   First step: Interview five HR or finance leads at Bengaluru and Pune startups about how they pay claims, and list every bank-validation or payout failure they remember from the last year.

3. Tool-identity guard for MCP servers in agent backends (score 4.0; effort 3, cost 1, fit 4)
   A Java or Python library and sidecar that pins each MCP tool to a verified provider and rejects calls that resolve to an unexpected server. It also enforces per-tool permissions and writes an audit trail of every tool resolution. Sell it to teams that run several MCP servers inside internal agent platforms.
   Why now: A new arXiv paper shows an attacker-controlled MCP server can capture tool calls by advertising matching names and metadata, with no host or model compromise needed.
   First step: Build a 50-line MCP setup with two tool servers that expose the same tool name, and reproduce the misbinding before writing any guard code.

4. Vendor-neutral evaluation harness for clinical AI scribes (score 3.8; effort 3, cost 2, fit 4)
   A self-hosted harness that Indian hospitals and clinic groups run against AI scribe and note-summarisation vendors using their own de-identified encounter notes. It scores omissions, hallucinated medication or dosage lines, and consistency across repeated runs, so the clinical team picks a tool on measured behaviour. The doctor still signs off every note.
   Why now: MedCity News argues vendor exam scores don't reflect real clinical performance, and MDCalc's CrossCover shows clinicians now want warnings about when generative answers can't be trusted.
   First step: Ask two private hospital medical-records heads what they currently use to evaluate AI scribes, and record their failure examples in a spreadsheet.

5. Pre-authorisation and claim form filler for small Indian hospitals (score 3.5; effort 4, cost 2, fit 4)
   Staff upload a discharge summary and itemised bill, and an agent fills the insurer or TPA portal forms, flags missing fields, and queues the submission. A billing staffer reviews and submits every claim. It targets small hospitals that lose margin to rejected or delayed claims and cannot afford a full RCM vendor.
   Why now: OpenAI's computer-use agents are being tested by CVS Health, Cigna and Abridge on payer portals, so agents driving insurer web forms are now a live pattern, and small Indian hospitals still key these forms by hand.
   First step: Sit with one clinic's billing desk for a morning with their consent and map every field on their most-used TPA portal form.
