1. Java patch blast-radius bot for small Spring Boot teams (score 4.5; effort 3, cost 1, fit 5)
   A GitHub App that reads a library or patch version bump, lists which of the team's repositories call the changed APIs, and flags services still on vulnerable JDK or library versions. It is sold as a flat monthly fee to Indian SaaS teams with five to thirty Java services, who cannot afford enterprise supply-chain tools.
   Why now: Netflix's Quasar work on cross-repo API blast radius, combined with the Java4Shell Base64 decoder RCE and a critical OpenSSL overflow disclosed in the same week, makes patch triage across many services urgent.
   First step: Write a script that scans five of your own Maven or Gradle repos and lists every call site of a chosen library's changed methods, then check whether the output is useful to an engineer.

2. Lab report digitisation with an extraction-yield dashboard (score 4.2; effort 3, cost 2, fit 5)
   A per-report API for small diagnostic labs that OCRs printed reports into structured results and flags fields below a confidence threshold for a human to check. It tracks yield (the share of reports fully extracted without manual rework) alongside accuracy, and bills per report. The doctor still reads and signs off every result.
   Why now: A pathology foundation model paper reports headline AUCs on held-out slides, but labs and hospitals still need to know what share of real documents pass through unattended, which accuracy alone does not answer.
   First step: Collect 50 anonymised lab reports from a friendly clinic, run them through an open OCR plus LLM extraction pipeline, and measure the percentage that needs no manual fix.

3. Tests-as-data harness for AI-written Java services (score 4.2; effort 2, cost 1, fit 4)
   A library and CLI where customer-level test cases live as versioned YAML or JSON files outside the codebase, so coding agents cannot edit them. Each run replays the cases against a Spring Boot service and fails the build on any behavioural change. It is sold as a free core with a paid hosted dashboard to teams using Copilot or Claude Code on Java backends.
   Why now: Fowler's post on tests as data argues that AI-written code needs an external contract the agent cannot change, and deterministic simulation testing shows how to make such failures reproducible in distributed backends.
   First step: Take one Spring Boot endpoint, export ten request and response pairs as JSON files in a separate folder, and write a JUnit runner that replays them and fails on any diff.

4. Idle-reservation monitor for LLM agent sessions (score 4.0; effort 3, cost 1, fit 4)
   A middleware and dashboard that tracks how long each agent session holds a sandbox, container or connection while waiting on the model, and suggests pooling or early release. It targets teams running agents on managed runtimes and charges a monthly fee based on reserved environment-hours saved.
   Why now: A paper on Bedrock AgentCore shows agents waiting a median of 2.7 seconds per reply while holding full environments, so environment exhaustion arrives before CPU limits; TideCache shows how much serving cost depends on memory placement.
   First step: Instrument one agent loop you already run so it logs time spent waiting on model calls versus time holding the environment, and compute the idle share over a day.

5. Clinical AI eval kit for Indian hospital buyers (score 3.8; effort 3, cost 2, fit 4)
   A small, reproducible evaluation harness that a hospital's IT or quality team can run on any vendor's AI report summariser or image-triage tool, using their own de-identified cases. It produces a sensitivity, specificity and drift report per site, sold as a yearly subscription to mid-sized private hospital groups and diagnostic chains.
   Why now: MedCity's piece on misleading vendor exam scores and a pathology-AI paper reporting 98% sensitivity with 81% specificity both show buyers need local, repeatable validation before deployment.
   First step: Interview two hospital quality or IT heads in your network about how they currently check vendor AI claims, and write down the three checks they run by hand.
