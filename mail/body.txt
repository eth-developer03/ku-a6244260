BUSINESS IDEAS
1. Doctor-verified lab report digitiser for small clinics (score 4.2; effort 3, cost 2, fit 5)
   A web tool where a clinic uploads scanned lab reports (common in Indian diagnostic labs), OCR extracts test names, values and units into structured records, and the doctor must approve each value in a review queue before it enters the patient record. Export is to the clinic's existing EMR or an ABDM-compatible format, sold per clinic per month.
   Why now: MDCalc's CrossCover shows clinicians now want a visible trust layer over AI output, so a human-approval step is a selling point rather than friction.
   First step: Collect 20 real scanned lab reports from a friendly clinic (with consent and anonymisation) and measure how often OCR gets units and reference ranges wrong.

2. Employer medical-claim reimbursement via UPI and IMPS (score 4.2; effort 3, cost 2, fit 5)
   A B2B API for Indian SMEs to run employee medical, wellness and LTA reimbursements: employees upload bills, OCR checks amounts and dates against policy caps, and approved claims pay out to verified bank accounts through a licensed payout partner. The product never holds customer funds, which avoids the custody and compliance cost that sank the closed-loop, card-based model.
   Why now: Flex's engineer #1 story shows that fixing benefits-payment friction for employees is a sharp, founder-led problem, and India's Indian-rupee payout rails make the same fix cheaper here.
   First step: Interview five HR or finance leads at 20-100 person companies about how they reimburse medical claims today, and note how long a payout takes and what they pay for it.

3. Test-as-data regression gate for AI-written code (score 4.2; effort 2, cost 1, fit 4)
   A GitHub Action and CLI that stores customer-level API tests as versioned JSON or YAML files outside the codebase, so an AI coding agent cannot edit them. It replays recorded production requests against a PR and blocks merges when response shapes or key values drift, with a per-repo pricing tier for small teams.
   Why now: Fowler's piece on tests as data and AWS's regression framework that gates releases on production-traffic match rates both point to the same gap: teams need a contract that AI-generated code cannot quietly rewrite.
   First step: Write a single-file replayer that takes 30 recorded requests from one of your own services and fails the build when a response field changes.

4. Spend-capped LLM proxy priced in rupees for small Indian AI apps (score 4.0; effort 3, cost 1, fit 4)
   A self-hostable proxy that sits in front of OpenAI, Anthropic and Gemini APIs and enforces per-user and per-agent spend caps, a kill switch, and a trace of every call. It bills in INR for small Indian SaaS teams that cannot afford enterprise observability stacks, and it runs as a single container to keep support load low.
   Why now: Langfuse's new Rust AI Gateway and AWS's governed-agent reference architecture both show demand for tracing and control at the gateway, but both target large teams.
   First step: Build the spend-cap middleware for one provider and test it against a personal agent that loops, to confirm the kill switch stops calls within one request.

5. Guideline-grounded answer checker API for clinic chatbots (score 3.5; effort 4, cost 2, fit 4)
   A small API that takes an LLM answer and the source documents it claims to use, then flags sentences with no supporting passage from a curated, versioned set of guidelines the clinic chose. It returns a 'rumble strip' score and highlights unsupported claims for the doctor to review. It does not generate medical advice, only checks that the chatbot's citations exist and match.
   Why now: MDCalc is launching a tool specifically to tell doctors whether medical AI chatbot answers can be trusted, which validates demand for a verification layer.
   First step: Build a 50-question test set from one clinic's chatbot logs and manually label which answers have citations that actually support the claim.
